# 01 — Principles and Decision Records

**Read with:** `00_INDEX.md`. Evidence for the decisions is in `05_RESEARCH_NOTES.md`.

---

## 1. Principles

Every design choice in this folder follows from these five. When a spec is silent, decide by them.

1. **The ledger is the source of truth; weights are a cache of it.** Every real input is stored.
   Every slab records which entries trained it and can be rebuilt from them.
2. **One substrate, several clocks.** Fast memory and long-term memory are the same object (a
   low-rank slab) updated at different frequencies.
3. **The frozen base is the only teacher.** Synthetic training data is written by the frozen base
   while it reads real entries. The adapted model never trains on its own output.
4. **A slab's behaviour must not depend on which other slabs are loaded.** The set of loaded slabs
   changes every turn.
5. **Nothing is committed without a functional test.** Every write, merge, prune and rebuild is
   checked against held-out probes and rolled back on failure.

---

## 2. Decision records

Status values: `decided` (follow it), `needs-test` (follow it until the named experiment reports,
then confirm or replace), `superseded`.

### D-01 Ledger as source of truth
- **Decision:** All real inputs go to an append-only local store. Slabs are derived artefacts.
- **Why:** Gives exact unlearning, rollback, merge verification and base-model replacement. The
  PRD has no mechanism for any of these.
- **Status:** decided.

### D-02 Fast slab replaces a Titans-style associative memory (PRD Tier 1)
- **Decision:** Tier 1 is a rank-16 slab updated by a few gradient steps per turn.
- **Why:** Titans and Hope train their memory projections together with the backbone. Nested
  Learning's LLM experiment continues pre-training for 15B tokens; no frozen-base variant exists.
  Untrained projections attached to a frozen model inject noise. The PRD's own deprecation log
  also drops token-level fast-weight updates.
- **Status:** decided. The fast slab itself is `needs-test` (experiment E-L1, P2): if it adds
  nothing over recall, the per-turn clock is removed.

### D-03 Frozen base is the only teacher
- **Decision:** Derived samples are generated by the base with slabs disabled, reading cited
  ledger entries in context.
- **Why:** Removes the recursive self-training loop that causes model collapse. Makes a derived
  sample a function of its cited entries only, so a slab rebuilt without an entry has no
  first-order dependence on it (the limits are stated in `P08` §3).
- **Status:** decided.

### D-04 Independent per-slab gates
- **Decision:** Each slab's gate is a sigmoid of its own row-space energy. No normalisation across
  slabs. A top-k cap bounds how many contribute.
- **Why:** MoRA normalises scores across all ranks. With a hot set that changes per turn, that
  makes a slab's output depend on unrelated slabs (violates principle 4).
- **Evidence gap:** MoRA's results are for competitive gating. Independent gating is untested.
- **Status:** needs-test (experiment E-GATE, P1). Fallbacks, in order: keyed gate; competitive gate
  within a fixed training-time hot set.

### D-05 Functional tests gate every commit
- **Decision:** New-probe recall, neighbour retention, anchor KL, gate leak and refusal agreement
  are checked before any slab version goes live.
- **Status:** decided.

### D-06 Commits only at safe points
- **Decision:** A trained shadow slab goes live only at session start, at context eviction, or
  after an idle re-prefill.
- **Why:** Changing weights invalidates the KV cache computed under the old weights. The PRD's
  pointer swap does not avoid this.
- **Status:** decided. Stale commits are `needs-test` (experiment E-STALE, P2) and are off by default.

### D-07 Retrieval is a first-class path
- **Decision:** Ledger chunks are recalled into context every turn.
- **Why:** SEAL's best no-context recall after training on a passage is 47.0%. A systematic study
  of parametric RAG finds it loses fine-grained detail and works best combined with retrieval.
  Exact strings should come from recall; slabs carry vocabulary, style, skills and frequent knowledge.
- **Status:** decided.

### D-08 Time as text; supersession instead of decay
- **Decision:** Dates are plain text in samples, recall output and the system prompt. A newer
  contradicting entry supersedes an older one. Only the fast slab decays.
- **Why:** Age does not make a fact false. Blanket decay deletes facts that are still true.
- **Status:** decided.

### D-09 Forget by rebuild
- **Decision:** Forgetting a personal fact rebuilds the affected slabs without it. A trained
  `refusal` slab is used only to suppress knowledge the base itself holds.
- **Why:** TOFU finds gradient-based unlearning weak and damaging. For personal facts the frozen
  base is already the calibrated "does not know" state.
- **Status:** decided.

### D-10 Real-data rule
- **Decision:** Every training batch is at least 25% real tokens. Derived samples have generation
  depth 1. All real data is kept permanently.
- **Why:** The PRD's 2% figure has no support. Accumulating real data bounds collapse error
  (Gerstgrasser et al.); D-03 removes the loop itself.
- **Status:** decided. 25% is a starting value.

### D-11 Merge by co-activation and effective rank
- **Decision:** Merge candidates are slabs that fire together or have near centroids. They are
  packed without loss when their effective ranks fit in one slab; otherwise a merged slab is
  retrained from the ledger and accepted only if probes hold.
- **Why:** The PRD's weight-cosine > 0.92 rule would practically never fire: independent rank-8
  updates measured max |cos| 0.0011. Truncating two unrelated rank-8 slabs to rank 8 keeps 55% of
  the energy. Entry-wise merging methods (DARE, TIES) operate on dense matrices and destroy
  low-rank structure.
- **Status:** decided.

### D-12 Context-distillation training objective
- **Decision:** The slab is trained so the model without the source matches the base with the
  source in context (KL on answer tokens), plus raw-text CE, replay and anchor terms.
- **Why:** Reported to beat next-token training for knowledge adapters (Caccia et al.).
- **Status:** decided. Hidden-state matching is experiment E-HID (P3).

### D-13 Attachment points
- **Decision:** `q_proj` and `v_proj` in every layer.
- **Why:** All-layer attachment avoids late-layer-only plasticity. Attention projections are small.
- **Status:** decided. MLP attachment is experiment E-MLP (P3).

### D-14 Separate sentence encoder for recall and routing
- **Decision:** A small frozen sentence-embedding model produces chunk embeddings and slab centroids.
- **Why:** Embeddings must not change when slabs change. Mean-pooled causal-LM states retrieve poorly.
- **Status:** decided.

### D-15 Single process, two threads, plain PyTorch
- **Decision:** One serving thread and one worker thread share the base weights. No vLLM, no
  shared-memory ring buffer, no RPC.
- **Why:** One to seven users. vLLM does not support per-token gated adapters. The ledger replaces
  the ring buffer.
- **Status:** decided. Revisit if a second GPU is dedicated to training.

### D-16 Safety as a behavioural commit gate
- **Decision:** Refusal behaviour is protected by a KL-to-base term on a refusal probe set and by
  a refusal-agreement commit test.
- **Why:** The alternative, projecting gradients orthogonal to a refusal direction, does not
  guarantee unchanged behaviour in a non-linear network: other layers can change the activations
  feeding that direction. Behaviour has to be measured.
- **Status:** decided.

### D-17 Tool syntax by constrained decoding
- **Decision:** JSON validity comes from grammar-constrained decoding. `exec` slabs improve tool
  and argument choice.
- **Status:** decided.

### D-18 Development on a 0.5B base on CPU
- **Decision:** All mechanisms are built and tested on Qwen2.5-0.5B before any GPU work.
- **Why:** The available machine has no discrete GPU.
- **Consequence:** A 0.5B teacher writes poor derived samples. The evaluation harness has an
  `oracle` teacher mode that isolates this.
- **Status:** decided.

### D-19 OOV handling is optional and last
- **Decision:** Input-side embedding table, built in P5, shipped only if it beats its ablation.
- **Status:** decided.

### D-20 No closed-form edits to base weights
- **Decision:** Closed-form rank-1 edits of a base projection matrix (ROME-style) are not used.
- **Why:** They modify the frozen base. Their locality relies on keys of unrelated facts being
  near-orthogonal, which real hidden states are not. Fact updates are served immediately by
  supersession plus recall.
- **Status:** decided. A gated rank-1 *edit slab* is listed as extension X-3 in `P12`.

### D-21 Sealing as the stability mechanism
- **Decision:** A slab stops training when it reaches its token capacity. Sealed slabs receive no
  gradients.
- **Why:** Knowledge that no gradient touches cannot be overwritten. Interference can then only
  come through gating, which replay and retention tests cover.
- **Status:** decided.

### D-22 Slabs operate on standardised inputs
- **Decision:** Each adapted module's input is standardised with fixed per-dimension mean and
  standard deviation measured once on the frozen base (`P02` §2.1). Gate and update both use it.
- **Why:** Raised in external review (2026-11-11). Hidden states are anisotropic; a few
  high-variance dimensions and a large mean would open raw-energy gates on generic text. The
  statistics are frozen, not running, so committed slabs do not drift.
- **Evidence gap:** anisotropy of Qwen 2.5 projection inputs has not been measured here
  (I-P02-12 does it). Standardisation does not remove correlations.
- **Status:** needs-test (E-GATE compares `standardize` with `none`).

### D-23 CPU contention: time-slicing or a worker process
- **Decision:** `runtime.worker_mode` is `thread` with strict time-slicing and capped step time,
  or `process` with its own thread count and affinity (`P04` §7.1).
- **Why:** Raised in external review. PyTorch's intra-op thread count is process-wide, so two
  threads in one process cannot be given separate pools; the choice is not to overlap, or to
  separate processes.
- **Status:** decided; measured by G-5.

### D-24 No cross-slab replay by default
- **Decision:** `L_replay` uses only the training slab's own earlier samples. Neighbour replay is
  a recorded fallback (`role='replay'` in `slab_sources`).
- **Why:** Raised in external review. Replayed neighbour samples put one slab's entries into
  another slab's training batches without recording it, which made the forget guarantee false
  as written and would force multi-slab rebuilds.
- **Status:** needs-test (E-REPLAY).

### D-25 Rule-based cloze and starvation fallback for weak teachers
- **Decision:** Code-generated cloze samples are a first-class sample source; when the teacher's
  acceptance rate is below `teacher.min_accept_rate`, entries are trained from them alone. The
  consistency filter is off on `dev`.
- **Why:** Raised in external review. A 0.5B teacher will fail the filters most of the time.
- **Status:** decided. Filter settings and acceptance rate are stated in every report.

### D-26 Lineage and concatenation in compaction
- **Decision:** Slabs record a `cluster_id`; compaction prefers same-cluster pairs; pairs that do
  not fit one slab are concatenated into a multi-block slab under one gate before any lossy merge.
  `compact.pack_cos` is renamed `compact.pack_centroid_cos`.
- **Why:** External review read `pack_cos` as weight cosine (it is source-text similarity) and
  argued packing would never fire. The misreading showed the name was unclear; the worry that
  lossless packing is rare is fair. Concatenation is exact and always available.
- **Consequence:** total parameters on disk are not bounded; memory in use is (`P07` §9).
- **Status:** decided.

### D-27 Session pinning
- **Decision:** No slab is unloaded while a session holds a KV cache; overflow triggers a
  re-prefill (`P04` §5).
- **Why:** Raised in external review. Swapping a slab out leaves cached keys and values that
  were computed with it.
- **Status:** decided. Adding a slab mid-session remains an approximation (E-STALE).

### Review items not adopted
- **Soft-prefix or key-value token cache in place of the fast slab.** A learned prefix needs its
  own training and also changes the KV cache; plain retrieval into context already provides
  within-session recall. The observation behind it (L1 cannot help the triggering session) is
  correct and now stated in `P05` §1.
- **Per-thread `torch.set_num_threads` partitioning inside one process.** Not possible as
  described; see D-23.
- **Full covariance whitening `Σ^{-1/2}`.** A `d×d` matrix per module is too large; diagonal
  standardisation is used (D-22).

### D-28 Calibrated cap ranking; the cap is a safety bound
- **Decision:** The top-k cap ranks slabs by margin standardised with each slab's own frozen
  reference statistics (`m_ref`). The cap-binding rate is measured and reported.
- **Why:** Second external review (2026-11-11). Raw margins of separately trained slabs are not
  on a common scale, so a raw top-k is biased toward whichever slab has the larger scale. The
  review's "permanent starvation" is overstated (the cap only acts when more than `k` gates are
  open on one token), but the bias is real and the cap is where principle 4 can break.
- **Not adopted:** running z-scores (they would drift committed behaviour); removing the cap
  (unbounded sums of updates).
- **Status:** needs-test (E-GATE reports margin spread and cap-binding rate).

### D-29 Retraction instead of differentiating through QR
- **Decision:** `A` is re-orthonormalised after every optimiser step, with `R` folded into `B`
  and first-moment buffers moved into the new basis. No gradient passes through QR or a
  triangular solve.
- **Why:** Second review: differentiating through `R⁻ᵀ` is fragile if `A` loses rank. Also
  resolves the momentum-basis mismatch at canonicalisation that the review raised for the fast slab.
- **Correction to the review:** its claim that `d(log e)/de = 1/e` explodes at the clamp floor
  ignores the sigmoid; the product is bounded when `τ ≤ 1`. That constraint is now enforced.
- **Status:** decided.

### D-30 One gate function for training and inference
- **Decision:** `w = max(0, (sigmoid(m) − δ)/(1 − δ))` everywhere; no inference-only cut-off.
  New slabs start with the gate open (`phi_init = −1.1`).
- **Why:** Second review: an inference-only cut creates a mismatch and a jump at the boundary.
  Working through the fix showed a further problem the review did not raise: with the old
  closed-start initialisation a new slab (`B = 0`) would sit in the zero region and get no gradient.
- **Status:** needs-test (E-GATE compares open-start and closed-start).

### D-31 Greedy rollouts gate commits
- **Decision:** Commit test 6 decodes probes greedily and fails on low match or any degenerate output.
- **Why:** Second review: teacher-forced NLL can pass while free generation loops or stops early.
  This reverses the earlier rule that generation metrics never gate a commit.
- **Status:** decided.

### D-32 Routing by recall hits and multiple centroids
- **Decision:** A turn loads first the slabs whose source entries were recalled, then slabs
  ranked by their best of up to four k-means centroids.
- **Why:** Second review: one mean centroid over 100–200 entries is too generic for niche
  queries. (Its "norm decay" point does not apply; centroids were already normalised.) Recall
  hits go further than the review's fix: retrieval has already located the exact entries.
- **Status:** decided.

### D-33 Ledger write discipline and block embedding store
- **Decision:** Busy timeout on every connection; no model work inside a transaction; bulk
  writes in small batches; embeddings in fixed blocks with a validity mask and zero-on-remove.
- **Why:** Second review. Its stated mechanism (FTS5 blocking readers in WAL mode) did not
  reproduce: 1,438 reads, no errors, 14 ms maximum during a 20,000-row FTS transaction. The same
  test showed the real problem: a second writer fails immediately without a busy timeout and
  waited 1.7 s with one, and the serving thread writes every turn.
- **Status:** decided.

### Second review: items not adopted
- **Position padding or position-id override for distillation.** The premise (hidden states
  carry rotary phases that the slab must model) does not hold for rotary encoding, which acts on
  relative offsets inside attention, and the loss compares output distributions. Padding the
  student with dummy tokens would change its context. A check is added instead (I-P03-10), with
  the override as the remedy if a base model fails it.
- **Changing the default attachment away from `q_proj`, `v_proj`.** The grouped-attention
  observation is correct but its effect is an empirical question; E-MLP now compares five
  attachment sets.
