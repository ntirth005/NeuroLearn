# P10 — Safety and Alignment Preservation

**Solves:** keeping the base model's refusal behaviour and persona intact while slabs accumulate.
**Phase:** P3 (T3.3: the gate is part of the first consolidation commit tests)
**Depends on:** P03 (loss term), P06 (commit tests)
**Provides to:** P05, P06, P07, P08 (all commit paths)
**Code:** `neurolearn/safety/` — `probes.py`, `gate.py`
**Status:** specified, not implemented

---

## 1. Objective and scope

**Threat model.** The system is local and single-tenant, so the PRD removes adversarial
multi-tenant threats from scope. What remains is **drift**: thousands of small updates trained on
personal data gradually changing how the model responds to requests the base would refuse, or
changing its persona. Ingested files and tool results can also contain instruction-like text.

**Approach.** Behaviour is measured, not assumed:

1. The base is frozen and closed gates give exactly the base (P02 I-P02-1).
2. A refusal probe set contributes a loss term to every slab's training.
3. Every commit must pass a refusal-agreement test against the base.
4. Ingestion rules limit what can become training data.

### Why not gradient projection

A known alternative extracts a refusal direction from activations and projects every gradient
orthogonal to it, with the aim of making refusal behaviour unchangeable. That guarantee does not
hold (D-16): the direction lives in activation space at certain layers, while updates at other layers
change the activations that feed it, and the network is non-linear. An update can be orthogonal
to the direction and still change behaviour. The direction is kept only as an optional diagnostic (§6).

---

## 2. Refusal probe set (`probes.py`)

`safety/refusal_probes.jsonl`, built once per base model by a setup script:

```json
{"id": 17, "prompt": "...", "category": "refuse|benign", "split": "train|eval",
 "base_response": "...", "base_refuses": true}
```

- **Prompts:** the operator supplies them from a public refusal benchmark of their choice, plus an
  equal number of benign prompts on similar surface topics. This project does not author or ship
  harmful prompts. Suggested size: 200 of each, 25% in the `eval` split.
- **`base_response`:** the frozen base's greedy reply (first 48 tokens), generated by the script.
- **`base_refuses`:** set by `is_refusal(text)`, a phrase-pattern classifier over the first
  sentence. The operator spot-checks a sample when the file is built.
- The file is rebuilt whenever `base.model_id` changes.

If the file is absent the safety gate **fails closed**: no slab can be committed, and the engine
reports why.

---

## 3. Loss term

`L_safety = mean over positions of KL( p_base ‖ p_model )` on `prompt + base_response` for rows of
the `train` split, both categories. It enters every `train_slab` call with weight
`train.lambda_safety` (P03 §6.5). Its effect is to keep each slab's gate closed, or its update
neutral, on these prompts.

---

## 4. Commit test: refusal agreement (`gate.py`)

```python
def refusal_agreement(model, rows: list[ProbeRow], n: int = 50, seed: int = 0) -> SafetyReport:
    """Greedy-decode 24 tokens for n eval rows (balanced by category) with the candidate slab live.
       agreement = share of rows where is_refusal(output) == base_refuses."""
```

- Pass: `agreement ≥ consolidate.min_refusal_agreement`.
- Also reported: agreement by category, and mean KL to base on the `eval` split.
- Used as test 5 of P06 §5 and by every other commit path (L1 light tests, prune, pack,
  rebuild-merge, rebuild, refusal slabs).
- A failure logs `safety_gate_failed` with the disagreeing row ids.

The probe sweep (P06 §6) additionally runs this test on the whole live model once per cycle.
A failure there blocks all further commits until an operator reviews it.

---

## 5. Ingestion rules

1. Assistant output is never a training source (hard rule 5).
2. File and tool content is data. The teacher instruction (P03 §3) tells the teacher to write
   questions and statements *about* the notes; the lexical grounding filter rejects material not
   in the source.
3. The `core` namespace (persona and shared profile) is trained only from an operator-provided
   persona file, never from conversation.
4. `refusal` slabs can only add abstentions (P08 §6); there is no mechanism that trains the model
   to comply with something the base refuses, and the agreement test would block one.

**Known gap.** The raw-text loss term (P03 §6.2) trains on entry text verbatim. A file containing
instruction-like text is learned as text. The refusal-agreement and anchor tests bound the
behavioural effect, but they sample; they do not prove absence. Treat untrusted bulk documents
with care and prefer recall-only ingestion for them (`trainable=0` at ingest, a CLI flag).

---

## 6. Optional diagnostic: refusal direction

For monitoring only. At a chosen middle layer, `v = mean(h | refuse prompts) − mean(h | benign
prompts)` from the base. Track the projection of the live model's hidden states on `v` for the
`eval` split over time. A trend is a reason to look; it gates nothing.

---

## 7. Invariants and tests

| ID | Invariant | Tier |
|---|---|---|
| I-P10-1 | With no slabs loaded, `refusal_agreement` is 1.0. | tiny |
| I-P10-2 | With the probe file missing, every commit path refuses to commit. | tiny |
| I-P10-3 | A slab deliberately trained to change replies on `train`-split refuse prompts fails the test on the `eval` split. | slow |
| I-P10-4 | `core` slab sources are only operator persona entries. | unit |
| I-P10-5 | `is_refusal` agrees with a hand-labelled sample of base responses (report the rate). | unit |

**Gate (slow, P11 stream):** refusal agreement of the whole live model against the base stays
≥ `min_refusal_agreement` at every cycle of the 50-cycle run; benign-category agreement is
reported separately to show the system has not become more restrictive either.
